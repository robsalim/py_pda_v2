\# PDA Next-Gen (py\_pda\_v2)

Настольное приложение для сбора, регистрации и визуализации данных с промышленных контроллеров (Siemens S7, Modbus TCP) на базе \*\*PyQt6\*\*. Ведёт собственную историю сигналов (Historian), отображает живые графики и временные диаграммы в десктопном интерфейсе, а также транслирует их через встроенный веб\-вьювер.

\---

\#\# ⚡ Возможности

\- \*\*Промышленные драйверы\*\*:  
  \- Siemens S7-300 / S7-400 / S7-1200 / S7-1500 (через \`snap7\`).  
  \- Siemens S7-200 SMART (прямая адресация V-памяти: \`VW100\`, \`VD20\`, \`V100.3\`).  
  \- Modbus TCP-клиент (Master) и встроенный Modbus TCP-сервер (Slave/Bridge).  
\- \*\*Вкладка I/O Configuration\*\*:  
  \- Иерархическое дерево модулей и групп сигналов.  
  \- Таблица тегов со значениями в реальном времени.  
  \- Импорт/экспорт конфигурации в форматы CSV и JSON.  
  \- Массовое копирование переменных со сдвигом адресации.  
\- \*\*Вкладка Charts (Тренды)\*\*:  
  \- Живые и архивные графики с поддержкой Drag & Drop из дерева сигналов.  
  \- Измерительные курсоры X1/X2 с расчётом разницы во времени (ΔT) и точных значений по оси Y в легенде.  
  \- Мультиоконный режим графиков на одной рабочей панели.  
\- \*\*Вкладка Bits (Дискретный анализ)\*\*:  
  \- Автоматическая распаковка байтовых и целочисленных регистров (\`BYTE\`, \`INT16\`, \`UINT16\`) в битовую маску с построением временных диаграмм (таймлайн логических сигналов).  
\- \*\*Архиватор (Historian)\*\*:  
  \- Буферизованная асинхронная запись в БД пачками (Batch-режим).  
  \- Фильтрация по изменению (Change of Value / COV), интервалу и зоне нечувствительности (deadband).  
  \- Автоматическая очистка старых данных по сроку хранения (Retention Policy).  
\- \*\*Встроенный веб\-сервер\*\*:  
  \- Мониторинг графиков и битовых состояний в любом браузере (\`http://localhost:8082\` на базе сверхбыстрого движка uPlot).  
\- \*\*Темы оформления\*\*:  
  \- Поддержка тёмной и светлой темы интерфейса с сохранением состояния.

\#\# 💾 Выбор и сравнение баз данных

PDA Next-Gen поддерживает несколько вариантов СУБД для хранения архива тегов. Выбор базы зависит от количества сигналов, частоты опроса и сценария эксплуатации.

| СУБД | Преимущества | Недостатки | Рекомендуемый сценарий |  
|---|---|---|---|  
| \*\*SQLite\*\* \*(по умолчанию)\* | • Работает «из коробки», не требует установки стороннего ПО.\<br\>• Вся база хранится в одном локальном файле (\`data/pda\_local.db\`).\<br\>• Нулевые затраты на администрирование.\<br\>• Минимальное потребление ОЗУ. | • Блокировка на уровне файла при записи (не рассчитана на сотни параллельных клиентов).\<br\>• Падение производительности при архивах \> 15–20 ГБ.\<br\>• Ограниченные возможности удалённого подключения к файлу базы. | Локальные стенды, переносные ноутбуки наладчиков, небольшие машины (\< 200–300 тегов с записью 1 раз в секунду). |  
| \*\*PostgreSQL\*\* | • Высокая надёжность транзакций (ACID) и стабильность.\<br\>• Отличная масштабируемость при сотнях параллельных запросов.\<br\>• Полноценный сетевой доступ (к одной БД могут обращаться несколько операторов/инженеров).\<br\>• Развитые инструменты резервного копирования и репликации. | • Требует установки и первоначального администрирования сервера PostgreSQL.\<br\>• Требует больше ресурсов системы (ОЗУ, CPU) по сравнению с SQLite. | Постоянно работающие цеховые SCADA-станции, диспетчерские посты, средние и крупные проекты (\> 500 тегов). |  
| \*\*PostgreSQL \+ TimescaleDB\*\* | • Специализированная оптимизация под временные ряды (Time-Series Data).\<br\>• Автоматическое секционирование (чанкирование) по времени.\<br\>• Аппаратное сжатие данных (экономия до 70–90% дискового пространства).\<br\>• Молниеносная выборка исторических трендов за большие периоды. | • Необходима установка расширения TimescaleDB поверх PostgreSQL.\<br\>• Чуть более сложная процедура настройки политик сжатия и ротации. | Крупные архивы, высокая частота опроса (10–100 мс), сотни и тысячи аналоговых тегов с хранением истории за месяцы и годы. |  
| \*\*MySQL / MariaDB\*\* | • Широкая распространённость и простота интеграции с веб\-инфраструктурой предприятия.\<br\>• Быстрая обработка простых операций вставки/чтения.\<br\>• Наличие удобных графических инструментов (DBeaver, phpMyAdmin, MySQL Workbench). | • Менее эффективна для аналитических запросов по скользящим окнам времени, чем TimescaleDB.\<br\>• Менее гибкая система расширений под временные ряды. | Предприятия, где сервер MySQL/MariaDB уже развернут и поддерживается штатными администраторами. |

\> \*\*Настройка СУБД в программе:\*\*    
\> Переключение типа базы и ввод параметров подключения (хост, порт, логин, пароль, имя базы) осуществляются прямо из графического интерфейса во вкладке \*\*Database & Storage\*\*. Настройки сохраняются в локальный файл \`db\_config.json\` (файл защищён от попадания в git-репозиторий).

\#\# 💻 Системные требования

\- \*\*ОС:\*\* Windows 10/11 (или Windows Server 2016+)  
\- \*\*Python:\*\* версия 3.10 или выше (убедитесь, что при установке Python отмечена галочка \*«Add Python to PATH»\*)  
\- \*\*Драйвер Siemens:\*\* для работы библиотеки \`python-snap7\` требуется наличие DLL-файла \`snap7.dll\` в каталоге программы либо в системной папке (\`C:\\Windows\\System32\`).

\#\# 📥 Способы установки

Выберите наиболее удобный для вас вариант развёртывания.

\#\#\# Вариант 1\. Установка через Git (рекомендуется для обновлений)

1\. Клонируйте репозиторий на рабочий компьютер:  
   ```bat
   git clone https://github.com/robsalim/py_pda_v2.git
   cd py_pda_v2
   ```
2\. Перейдите к шагу \*\*«Инициализация окружения»\*\* ниже.

\---

\#\#\# Вариант 2\. Установка через скачивание архива (ZIP)

Этот вариант не требует установленного Git-клиента.

\#\#\#\# Способ А: Загрузка актуального кода репозитория целиком  
1\. Откройте страницу репозитория py\_pda\_v2 на GitHub.  
2\. Нажмите зелёную кнопку \*\*\`\<\> Code\`\*\* вверху страницы и выберите \*\*\`Download ZIP\`\*\*.  
3\. Распакуйте скачанный архив \`py\_pda\_v2-main.zip\` в любую удобную папку (например, \`C:\\SCADA\\py\_pda\_v2\`).  
4\. Перейдите в распакованную папку.

\#\#\#\# Способ Б: Загрузка стабильной версии из Releases  
1\. Перейдите в раздел \*\*Releases\*\* репозитория.  
2\. Выберите нужную версию и в блоке \*\*Assets\*\* скачайте \*\*Source code (zip)\*\*.  
3\. Распакуйте архив в целевой каталог.

\#\#\# Инициализация окружения (для всех вариантов)

В корневой папке проекта запустите установочный скрипт:  
   ```bat
setup.bat  
   ```
Скрипт автоматически:  
\- создаст изолированное виртуальное окружение \`.venv\`;  
\- обновит менеджер пакетов \`pip\`;  
\- установит все необходимые зависимости из \`requirements.txt\`.

\*(При необходимости ручной установки:)\*  
   ```bat  
python \-m venv .venv  
.venv\\Scripts\\activate  
pip install \--upgrade pip  
pip install \-r requirements.txt  
   ```

\---

\#\# 🚀 Запуск программы

\#\#\# Быстрый запуск (Windows)  
Дважды щёлкните файл **`run.bat`** — приложение запустится в фоновом режиме без всплывающего черного окна командной строки (\`pythonw main.py\` с использованием созданного \`.venv\`).

\#\#\# Запуск через терминал (с выводом логов)  
Если требуется отслеживать системный вывод и сообщения об ошибках в консоли:  
   ```bat
.venv\\Scripts\\activate  
python main.py  
   ```

\#\#\# Веб-интерфейс  
Встроенный веб\-сервер запускается параллельно с основным приложением:  
\- Ссылка: \`http://localhost:8082\`  
\- Адрес и порт при необходимости можно переопределить в файле \`config.py\` (параметры \`WEB\_HOST\` и \`WEB\_PORT\`).

\---

\#\# ⚙️ Конфигурация (\`config.py\`)

| Параметр | Описание |  
|---|---|  
| \`DB\_CONFIG\` | Базовые параметры подключения к СУБД по умолчанию. |  
| \`WEB\_HOST\`, \`WEB\_PORT\` | Сетевой интерфейс и TCP-порт для встроенного веб\-сервера. |  
| \`DEFAULT\_MODBUS\_SERVER\_PORT\` | Порт встроенного Modbus TCP-сервера (по умолчанию 502; учтите, что для порта 502 могут потребоваться права администратора). |  
| \`JOURNAL\_CONFIG\` | Настройки историка: глубина буфера, размер пачки сохранения, интервалы и retention policy. |

\#\# 📁 Структура проекта

```text  
py\_pda\_v2/  
├── main.py             \# Точка входа приложения (GUI \+ диспетчеризация веб\-сервера и драйверов)  
├── config.py           \# Конфигурационные константы и параметры по умолчанию  
├── web\_server.py       \# Бэкенд встроенного веб\-сервера (FastAPI / Starlette)  
├── setup.bat           \# Скрипт автоматического создания .venv и установки библиотек  
├── run.bat             \# Скрипт быстрого запуска без окна консоли  
├── requirements.txt    \# Зависимости проекта  
├── core/               \# Ядро системы:  
│   ├── tag\_registry.py \# Оперативный реестр тегов (TagRegistry)  
│   ├── tag\_point.py    \# Внутреннее представление переменной процесса  
│   └── historian.py    \# Менеджер исторической архивации данных  
├── database/           \# Модуль работы с БД:  
│   ├── collector.py    \# Фоновый сборщик и батчер архивных данных  
│   ├── db\_service.py   \# Абстракция и слой адаптеров (SQLite, PostgreSQL, MySQL)  
│   └── init\_db.py      \# Скрипт создания структуры таблиц  
├── drivers/            \# Промышленные протоколы:  
│   ├── snap7\_driver.py       \# Клиент к ПЛК Siemens S7  
│   ├── snap7\_s200\_driver.py  \# Драйвер для Siemens S7-200 SMART  
│   ├── modbus\_client\_driver.py \# Драйвер Modbus TCP Master  
│   └── modbus\_server\_driver.py \# Драйвер Modbus TCP Slave  
├── models/             \# Дата-классы сигналов, соединений и точек данных  
├── ui/                 \# Пользовательский интерфейс PyQt6 (окна, тренды, биты, настройки)  
├── web/                \# Статические ресурсы веб\-вьювера (HTML, JavaScript/uPlot, CSS)  
└── tests/              \# Набор модульных и смоук-тестов  
```
